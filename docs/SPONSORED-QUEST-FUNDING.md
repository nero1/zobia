# Sponsored quest funding

- Creation reserves Credits from the submitting user's main wallet: **reward × application limit**, plus the daily-deck budget rounded up to whole Credits when daily distribution is enabled. The form shows the reserve before submission. Administrators fund their own submissions; assigning a campaign manager does not debit that manager.
- Each daily assignment reserves its completion reward and impression charge before entering a deck. Daily and total caps include those commitments. A blank action means Messages; only supported activity actions are accepted. Reach estimates include reward funding.
- A creator application pays its configured creator share once, after review. In **Admin → Sponsored Quests → Review applications**, read the completion proof and approve or reject it. Web/PWA and Vite Android use the same review flow. Completing or retrying an application cannot reopen a paid decision.
- Reward, action, CPM, share and application-limit terms are fixed after funding. Only the original payer can increase the daily-deck budget; that increase reserves additional wallet Credits atomically. Closed/refunded campaigns require a new campaign.
- Unused daily rewards return to the reserve after their assignment day ends. Cancellation or expiry refunds unused whole Credits through the durable worker. Existing daily reservations are honored until expiry; completed creator applications retain funding until reviewed. The platform retains a final fractional Credit below one Credit as recorded rounding. Funded historical records remain for reconciliation.
- An older campaign is paused with `funding_required` during upgrade. It is never charged silently. Its owner or an administrator can use **Reserve up to … Credits** to fund it explicitly; the caller's own wallet pays. Correct an expired deadline or insufficient legacy application limit before funding. Alternatively cancel it and create a new funded campaign.
- Apply the schema update through **GitHub → Actions → Database Setup → apply** before redeploying. Rebuild the Vite/Capacitor APK afterward. Fresh installations still use the one consolidated migration. Existing installations receive the verified `2026-10-25-sponsored-funding.sql` upgrade without wiping content.
- The existing daily job and durable worker release reservations and deliver refunds in bounded batches. Monitor failed tasks and admin alerts for refunds requiring attention. No cron frequency change is required.
